# `auto` capture on a stock host — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make "select a process, pick `auto`, press Start" produce a real capture — and its 3D substrates — on a stock Ubuntu host with nothing weakened, by giving the region picker a perf-free sampler, and by making the desktop tell the truth about which targets and modes can actually run before the operator commits to one.

**Architecture:** Two halves that meet at one seam. The **producer** half is `cli/`: `auto` is a two-stage pipeline whose second stage (`asmspy_engine_dataflow`, pure ptrace) already works unprivileged on this host, and whose first stage (the region picker) is the only thing that needs `perf_event_open`. A third sampler — PTRACE residency → CALL-target expansion → `int3` entry-arrival confirmation — slots into the same seams `--sampler=sw` already occupies, and a *reactive* fallback chain reaches it when the others are refused rather than only when their substrate is absent. The **consumer** half is `desktop/`: the attach verdict and the capability probe both currently report inferences as facts, so the picker mislabels every row and the patch bay offers modes that cannot run. Both become measurements, joined by one pure predicate in `live/budget.{h,cpp}` — the tree's established home for rules that can be wrong.

**Tech Stack:** C11 (`cli/`, `src/`), C++17 + Dear ImGui 1.91.9b-docking + nlohmann/json (`desktop/`), GNU make, Docker lanes.

### Task 1: `probe_attach` reports what it measured

**Files:**

- Modify: `desktop/src/live/inspect.h` (document the new probe on `AttachFacts`)

**Interfaces:**
- Consumes: nothing from earlier tasks.
- Produces: `AttachFacts::target_opted_in` is now genuinely set by the probe, and `is_kthread` means what it says. No signature change. Task 3 and Task 4 read the resulting verdict.

**Two invented facts, one function.** M9. `readlink("/proc/<pid>/exe")` failing means "not ours to read" far more often than "kernel thread", and the verdict checks `is_kthread` (`inspect.cpp:73`) *before* `!same_uid` — so a process owned by another user is reported as having no address space at all. Meanwhile the one fact that would turn "maybe" into "yes" for 12 of 15 Firefox processes is a field nothing outside the test suite ever writes.

The probe for "can I attach" is `open("/proc/<pid>/mem", O_RDONLY)`: it runs the kernel's own `ptrace_may_access(PTRACE_MODE_ATTACH_FSCREDS)` — the same check `PTRACE_ATTACH` runs — and changes no state. **It is NOT `PTRACE_SEIZE`.** A SEIZE probe was measured to leave the target seized: every `PTRACE_DETACH` returned `ESRCH` because `man 2 ptrace` requires the tracee to be in a ptrace-stop for it, and the victim reads `State: t (tracing stop)` afterwards. Do not use SEIZE here.

```c
/* Is this target under a non-trivial LSM label? /proc/<pid>/attr/current is
 * world-readable and reads "unconfined" (or is empty/absent) when it is not.
 * This does NOT decide attachability -- AppArmor's profile_tracee_perm
 * early-returns for an unconfined tracer, and snap's own profile #includes
 * abstractions/base, which grants ptrace (tracedby) unqualified. It decides
 * only which REMEDY is honest. */
static int asmspy_target_is_confined(pid_t pid) {
    char path[64], buf[128];
    FILE *f;
    size_t n;
    snprintf(path, sizeof path, "/proc/%d/attr/current", (int)pid);
    f = fopen(path, "r");
    if (!f)
        return 0;
    n = fread(buf, 1, sizeof buf - 1, f);
    fclose(f);
    buf[n] = '\0';
    return n > 0 && strncmp(buf, "unconfined", 10) != 0;
}
```

**Files:**

```c

 * `out` with up to `max` ranked candidates and returns the count, 0 for a
 * window that observed nothing (a retry, not a verdict), or <0 for a
 * self-skip with `why` filled. */
int asmspy_ptrace_sample(pid_t pid, const asmspy_syms_t *syms,
                         const char *module, asmspy_cand_t *out, int max,
                         int window_ms, char *why, size_t whylen);
```

**Three phases, because residency alone is measurably wrong.** M7 and M8. Phase 1 SEIZEs every tid, INTERRUPTs at ~997 Hz, reads the PC with `GETREGSET`, CONTs. Phase 2 widens the shortlist with direct-CALL targets via the existing `asmtest_disas_call_target` (`src/disasm.c:419-425`) — that is what reaches a callee residency never samples. Phase 3 confirms with an `int3` at each candidate entry and counts arrivals, reusing the engine's existing `rgn_plant_bp` / `rgn_race_to_entry` / `rgn_disarm_entry`.

**Six corrections the prototype needed. Every one is a defect the naive version shipped:**

1. **Signal handling is not optional.** The prototype `waitpid()`ed and unconditionally `PTRACE_CONT`ed with `sig=0`. Against a 100 Hz `ITIMER_REAL` victim that **destroyed 89% of the target's SIGALRMs and collapsed its throughput ~99%** (2 utime ticks and 0 forward-progress lines per 2 s, against 200/93 at baseline and after detach). The "~1% cost, no perturbation" figure holds only for a signal-free spinner. Discriminate group-stops from signal-deliveries with `PTRACE_GETSIGINFO` / `PTRACE_EVENT_STOP` and **re-inject**: `man 2 ptrace` — "If sig is 0, then a signal is not delivered."
2. **`PTRACE_O_TRACECLONE`, or you kill the user's process.** `cli/asmspy_engine.c:2954-2957` states it outright: a thread that was never seized, reaching the shared `int3`, "would take a SIGTRAP with no tracer and DIE." The prototype passed options `0`.
3. **`/proc/<tid>/stat`'s `utime+stime` cannot discriminate at this window.** `CLK_TCK` is 100 (10 ms ticks) and `AUTO_WINDOW_MS` is 400: measured, **every** thread of `threads_victim` shows a delta of 0 ticks. `/proc/self/schedstat` reads `0 0 1` (`kernel.sched_schedstats=0`, needs root). The working discriminator is **`/proc/<tid>/syscall`** — readable precisely because we are the tracer — which prints the literal `running` for an executing thread and a syscall number for a blocked one.
4. **Rank on time-to-first-arrival, not a censored count.** Under a per-candidate hit budget the counts saturate and tie: measured `tiny_callee 50 arrivals residency=1` tied with libc's `sched_yield 50 arrivals residency=1`, broken by the very metric the entry rule exists to replace. Time-to-first-arrival separates cleanly (105 µs vs 6125 µs).
5. **`asmtest_disas_call_target` is Capstone-gated** and returns 0 silently without it. Phase 2 must say "no Capstone — call-target expansion skipped", not quietly degrade to phase 1.
6. **The `'R'` state filter bounds COST, not correctness.** 100 threads cost the same as 1 (0.27% of the window), but the ranking still put `clock_nanosleep` above `worker` 11:3 with the filter on. Keep it for cost; do not credit it with accuracy.

### Task 10: `PR_SET_DUMPABLE`, so a granted capability actually produces a codeimage

**Files:**
- Modify: `cli/asmspy.c` (`main`, before any capture)
- Test: `cli/cli_smoke.sh`

**M16, and it is the trap that makes the documented remedy fail silently.** A file-capability `execve` marks the process non-dumpable, `/proc/self/*` flips to `root:root`, and `src/codeimage.c:244`'s `open("/proc/self/clear_refs", O_WRONLY)` gets EACCES — so a `setcap`'d asmspy emits **no codeimage**, which gates every 3D scene, and blames a kernel config (`CONFIG_MEM_SOFT_DIRTY`) that is `=y`. Measured A/B against a capped binary built in scratch.

```c
    /* A file-capability execve marks us non-dumpable, which flips /proc/self to
     * root:root and makes codeimage's own soft-dirty probe fail with EACCES --
     * so a `setcap cap_perfmon+ep asmspy` produces perf access and NO codeimage,
     * blaming a kernel config that is enabled. Restore dumpability before any
     * capture. Guarded, so the normal unprivileged path is untouched. */
    if (prctl(PR_GET_DUMPABLE) != 1)
```

## Deferred — tracked, deliberately not in this plan

- **A merged live tab.** `shell_sync_live_tab` mirrors ONE Recording, so a sweep's substrates never co-exist until the user disconnects and `File > Open`s. Merging them **reverses a design premise stated in `e164d9d1`** and concatenates per-leg `seq`/`rbase`/`basis` spaces that the Loom, Slice and Scrubber all read. It needs a design decision (merged tab *beside* the per-leg tab?) before any code, and Task 12's scorer is what makes the current behaviour honest in the meantime.
- **`ymm16-31`, then ZMM, in `vec_width`/`read_ymm`** (`src/dataflow_ptrace.c:349-355`). `__memmove_evex_unaligned_erms` is a **256-bit** routine that dies in the prism on the high register index, not on ZMM — so ymm16-31 is the cheap half and is what the hot glibc paths actually use. ZMM needs a CPUID(0xd) leaf walk.
- **Reader-side routine identity from `codeimage.bytes`.** A `--serve` session file carries no `code` header, so `diff.cpp:61-70` can never prove two sides are the same routine — but the file already carries the routine bytes. A reader-side sha closes it with zero producer change and zero golden churn. Cheap; just not on this plan's critical path.
- **Thread-aware picking.** `auto` cannot be combined with `--tid` (`cli/asmspy.c:4654`). Carrying `PERF_SAMPLE_TID` (or the ptrace sampler's own tid) through to candidate ranking would give a thread-aware *pick*, which is not the same as a thread-scoped capture — be explicit about that distinction or it will be mis-sold.
- **Opening `launch` to `auto`/`dataflow`.** The refusal at `serve_launch_mode_ok` (`cli/asmspy.c:4709-4726`) is architectural: those engines attach through `src/dataflow_ptrace.c`'s own SEIZE sites, which never consult `g_already_traced`. Large, and for a snap target measured broken anyway.
